第一步 · 授权

连上 GitHub 仓库

网站托管在 GitHub Pages，后台通过 GitHub API 直接把修改提交进仓库。需要你的 个人访问令牌 (PAT)，令牌只保存在本浏览器，不会上传、也不会写进仓库或网页源代码。

如何生成 PAT？↗

PAT 权限：只读「Contents」即可浏览；要保存修改需勾选 Contents 的 Read and write。

多人一起维护怎么办？（不要把令牌给别人）

1 · 各自用自己的令牌（推荐）
让协作者去 Fine-grained tokens 自己生成一个，只授权这一个仓库、权限只勾 Contents: Read and write、有效期设 7~30 天。你随时能在 GitHub 上单独吊销某一个人的令牌，不影响其他人。

2 · 让他们提交到独立分支，由你合并
上面「分支」一栏填 draft-张三 之类，改动只进这个分支，main 和线上站点完全不受影响。他们在 GitHub 上发 Pull Request，你审核后合并即可。

3 · 不给后台权限，只收内容
对方把比分、花名册、照片发给你，由你统一录入——最省心，也最安全。

⚠️ 后台的「站点口令」只是界面门禁（用于防误入），不是权限边界：真正的写权限由 GitHub 令牌决定。所以口令可以告诉别人，令牌绝对不能。
